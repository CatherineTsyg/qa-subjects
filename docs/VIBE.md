# Отчёт «на 4»: вайб-версия

## Промпты

Каждый промпт к агенту — дословно, по порядку.

### 1. Первичная генерация

```
В папке vibe/ сделай Django-приложение «база ответов по предметам» по AGENTS.md.

Что нужно:
- предметы (категории) добавляются через админку;
- регистрация, вход и выход пользователей;
- пользователь может задать вопрос по предмету;
- к вопросу пользователи пишут ответы;
- ответу можно поставить лайк или дизлайк, самые залайканные ответы показываются первыми;
- к ответу можно прикрепить фото и документы;
- PostgreSQL, запуск через docker compose, .env.example, тесты.

Когда закончишь — подними приложение через docker compose, выполни миграции и прогони тесты,
убедись, что всё работает. В конце кратко перечисли, что сделано и как запустить.
```

Результат: за один промпт агент сделал рабочее приложение — приложения `accounts` (регистрация, вход, выход) и `qa`
(предметы, вопросы, ответы, голоса, вложения), админку, `docker-compose.yml` (web + PostgreSQL 16 с healthcheck),
`.env.example` и 33 теста. Приложение поднялось, миграции применились, тесты прошли.

### 2. Исправления по ревью

```
Ревью кода в vibe/. Исправь следующее и на каждый пункт 1–4 добавь тест:

1. Автор не должен голосовать за собственный ответ: запрещай это во вью голосования и скрывай кнопки голосования у своих ответов.
2. В answer_vote возможна гонка: при двух одновременных запросах второй create падает с IntegrityError (ошибка 500). Сделай голосование устойчивым к повторным запросам (транзакция + select_for_update или обработка IntegrityError).
3. Ограничь число файлов в одном ответе — не больше 10 с учётом уже прикреплённых; при превышении — ошибка формы.
4. Сохранение ответа и его вложений в AnswerCreateView и AnswerUpdateView оберни в одну транзакцию.
5. В settings.py DEBUG по умолчанию должен быть False, если переменная не задана (в .env.example оставь True).
6. Удали vibe/.gitkeep.

После правок прогони тесты в docker compose и перечисли, что изменилось.
```

Результат: все 6 пунктов исправлены за один промпт, добавлено 7 тестов (всего 40, все проходят).

### Ревью №1 (после промпта 1)

Что проверялось: чтение всего кода, `manage.py test` (33/33 OK), `makemigrations --check` (без изменений),
число SQL-запросов на страницах при 10 ответах и 100 голосах (3–6 запросов, N+1 нет), ручная проверка в браузере.

Сделано хорошо: уникальность голоса и допустимые значения (±1) — ограничениями в БД; рейтинг — агрегатом `Sum`;
права автора/staff на правку и удаление; все изменяющие действия — только POST с CSRF; проверка расширения и размера
файлов, файлы сохраняются под случайными именами; секреты — из окружения; тесты на права и граничные случаи.
