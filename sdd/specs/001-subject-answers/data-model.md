# Data Model: База ответов по предметам

**Feature**: `001-subject-answers` | **Date**: 2026-11-10

Модели реализуются в Django-приложениях `accounts` (пользователи — встроенная модель) и `qa`
(домен). Все ограничения целостности, которые выражаются схемой, задаются в БД.

## Сущности

### User (встроенная `auth.User`)

| Поле | Тип | Ограничения |
|------|-----|-------------|
| `id` | BigAutoField | PK |
| `username` | CharField(150) | уникальное, обязательное |
| `password` | CharField(128) | хеш пароля, обязательное |
| `is_staff` | BooleanField | права staff |

Роли: посетитель (не аутентифицирован), пользователь, staff. Отдельная модель профиля не нужна.

### Subject

| Поле | Тип | Ограничения |
|------|-----|-------------|
| `id` | BigAutoField | PK |
| `name` | CharField(120) | уникальное, обязательное |
| `description` | TextField | может быть пустым |
| `created_at` | DateTimeField | `auto_now_add` |
| `updated_at` | DateTimeField | `auto_now` |

Ограничения БД: уникальность `name`. Удаление: запрещено, если есть хотя бы один вопрос
(`Question.subject` → `on_delete=PROTECT`).

### Question

| Поле | Тип | Ограничения |
|------|-----|-------------|
| `id` | BigAutoField | PK |
| `subject` | FK → Subject | `on_delete=PROTECT`, `related_name="questions"` |
| `author` | FK → User | `on_delete=CASCADE`, `related_name="questions"` |
| `title` | CharField(200) | обязательное, непустое |
| `body` | TextField | обязательное, непустое |
| `created_at` | DateTimeField | `auto_now_add` |
| `updated_at` | DateTimeField | `auto_now` |

Ограничения БД: `CheckConstraint(title != "")`, `CheckConstraint(body != "")`.
Индекс: `(subject, -created_at)` для страницы предмета. Сортировка — от новых к старым (FR-023).
Удаление вопроса каскадно удаляет ответы, их голоса и вложения.

### Answer

| Поле | Тип | Ограничения |
|------|-----|-------------|
| `id` | BigAutoField | PK |
| `question` | FK → Question | `on_delete=CASCADE`, `related_name="answers"` |
| `author` | FK → User | `on_delete=CASCADE`, `related_name="answers"` |
| `body` | TextField | обязательное, непустое, до 10 000 символов (валидация формы) |
| `created_at` | DateTimeField | `auto_now_add` |
| `updated_at` | DateTimeField | `auto_now` |

Ограничения БД: `CheckConstraint(body != "")`. Индекс: `(question)`.
Рейтинг не является полем модели: вычисляется как
`Coalesce(Sum("votes__value"), 0)` при чтении (FR-022).

### Vote

| Поле | Тип | Ограничения |
|------|-----|-------------|
| `id` | BigAutoField | PK |
| `answer` | FK → Answer | `on_delete=CASCADE`, `related_name="votes"` |
| `user` | FK → User | `on_delete=CASCADE`, `related_name="votes"` |
| `value` | SmallIntegerField | только `1` (лайк) или `-1` (дизлайк) |
| `created_at` | DateTimeField | `auto_now_add` |
| `updated_at` | DateTimeField | `auto_now` |

Ограничения БД:
- `UniqueConstraint(fields=["user", "answer"], name="vote_unique_user_answer")` — не более одного
  голоса на пару (FR-009);
- `CheckConstraint(condition=Q(value__in=[1, -1]), name="vote_value_allowed")`.

Индекс: `(answer)` для агрегата рейтинга. Самоголосование запрещено на уровне сервиса/формы
(FR-011); ограничение проверяется до записи.

### Attachment

| Поле | Тип | Ограничения |
|------|-----|-------------|
| `id` | BigAutoField | PK |
| `answer` | FK → Answer | `on_delete=CASCADE`, `related_name="attachments"` |
| `file` | FileField | `upload_to="attachments/%Y/%m/%d/"` |
| `original_name` | CharField(255) | очищенное имя файла |
| `content_type` | CharField(100) | определённый при проверке тип; используется в `Content-Type` ответа |
| `size` | PositiveBigIntegerField | размер в байтах |
| `created_at` | DateTimeField | `auto_now_add` |

Индекс: `(answer)`. Вложений на ответ — не более 5 (проверка формы и сервиса под блокировкой
ответа; счётчик не хранится отдельным полем). Файл удаляется вместе с записью
(`post_delete`-сигнал).

## Связи

```text
User 1 ──< Question >── 1 Subject
User 1 ──< Answer   >── 1 Question
Answer 1 ──< Vote >── 1 User          (уникальная пара user + answer)
Answer 1 ──< Attachment
```

- `Subject` 1 — N `Question` (удаление предмета запрещено при N > 0).
- `Question` 1 — N `Answer` (каскадное удаление).
- `Answer` 1 — N `Vote` (каскадное удаление, уникальность пары).
- `Answer` 1 — N `Attachment` (каскадное удаление, максимум 5).

## Правила валидации

| Правило | Уровень | Требование |
|---------|---------|------------|
| Уникальное имя пользователя | БД + форма | FR-004 |
| Пароль проходит валидаторы Django | форма | FR-004 |
| Предмет: уникальное непустое название | БД | FR-002 |
| Удаление непустого предмета запрещено | БД (`PROTECT`) + админка/сервис | FR-002 |
| Вопрос: заголовок 1–200 символов, непустой текст | форма + БД | FR-006, FR-021 |
| Ответ: текст 1–10 000 символов | форма + БД | FR-007, FR-021 |
| Голос: значение `1` или `-1`, уникальная пара | БД | FR-009, FR-010 |
| Запрет голосовать за свой ответ | сервис/форма | FR-011 |
| Расширение файла из белого списка | валидатор | FR-012 |
| Сигнатура содержимого соответствует расширению | валидатор | FR-013 |
| Файл не пустой, размер в пределах лимита | валидатор | FR-013 |
| Не более 5 вложений на ответ | форма/сервис | FR-012 |
| Права: автор ответа/staff для вложений; автор/staff для контента | представления/сервисы | FR-015, FR-016 |
| CSRF и аутентификация для всех POST | middleware/представления | FR-019 |

## Состояния и переходы

### Голос

```text
нет голоса ──лайк──▶ лайк ──дизлайк──▶ дизлайк
     ▲                 │                  │
     └──────снятие─────┴──────снятие─────┘
```

- Создание, замена и снятие выполняются в одной транзакции для пары «пользователь — ответ».
  Вставка идёт во вложенном `transaction.atomic` (точка сохранения): `IntegrityError` от
  уникального ограничения откатывает только попытку, после чего голос обновляется повторно.
  Результат — не более одного голоса (FR-009).

### Контент

- `Subject`: создан → (редактирование) → удалён, только если вопросов нет.
- `Question`: создан → (редактирование) → удалён; удаление каскадно удаляет ответы, голоса,
  вложения.
- `Answer`: создан → (редактирование) → удалён; удаление каскадно удаляет голоса и вложения.
- `Attachment`: добавлен (≤ 5) → удалён автором ответа или staff; файл удаляется с записью.

После любой изменяющей операции (включая админку и каскадные удаления) инвалидация кеша
регистрируется в сигналах `post_save`/`post_delete` через `transaction.on_commit` и выполняется
только после успешного коммита.

## Кешируемые представления данных

Ключи включают номер страницы; инвалидация выполняется сменой версии ключа, поэтому все страницы
становятся недостижимы одновременно.

| Назначение | Ключ |
|------------|------|
| Версия списка предметов | `qa:v1:subjects:list:version` |
| Страница списка предметов | `qa:v1:subjects:list:v{version}:page:{n}` |
| Версия ответов вопроса | `qa:v1:question:{id}:answers:version` |
| Страница ответов вопроса | `qa:v1:question:{id}:answers:v{version}:page:{n}` |

TTL страниц — 300 секунд; корректность обеспечивается инвалидацией, TTL — только страховка.
Ключи версий хранятся без TTL; инвалидация атомарно выполняет `cache.add(version_key, 1)` и
`cache.incr(version_key)`.
Страница ответов содержит общие данные: `id`, текст, автора, дату, рейтинг и метаданные
вложений; голоса текущего пользователя в значении нет.

### Инвалидация через сигналы

Приёмники `post_save`/`post_delete` в `qa/signals.py` регистрируют
`transaction.on_commit`-инвалидацию. Сервисы и представления ключи не удаляют.

| Событие модели | Инвалидация |
|----------------|-------------|
| `Subject` сохранён/удалён | версия списка предметов |
| `Question` сохранён/удалён | версия списка предметов и версия ответов вопроса |
| `Answer` сохранён/удалён | версия ответов вопроса |
| `Vote` сохранён/удалён | версия ответов вопроса, содержащего оценённый ответ |
| `Attachment` сохранён/удалён | версия ответов вопроса вложения |

Каскадные удаления отправляют `post_delete` для каждого объекта, поэтому удаление пользователя
(в том числе через админку) инвалидирует кеш его вопросов, ответов, голосов и вложений.
Подключение `post_delete`-приёмников отключает fast-delete Django; при `raw=True` инвалидация
пропускается.

### Персональные данные

Кеш страницы вопроса не содержит голос текущего пользователя. После чтения кеша одним отдельным
запросом выбираются голоса пользователя для ответов страницы; результат передаётся в шаблон для
подсветки кнопок. Для анонима запрос не выполняется, персональные данные в кеш не попадают.

## Объём данных и индексы

- Целевой объём: 10 000 вопросов, 100 000 ответов, до 100 одновременных пользователей.
- Индексы: `Subject(name)` (уникальный), `Question(subject, -created_at)`, `Answer(question)`,
  `Vote(answer)` + уникальный `(user, answer)`, `Attachment(answer)`.
- Пагинация списков — 20 элементов.
