# HTTP Contracts: База ответов по предметам

**Feature**: `001-subject-answers` | **Date**: 2026-11-10 | **Plan**: [../plan.md](../plan.md)

Приложение server-rendered: контракт описывает маршруты, методы, права, коды ответов и побочные
эффекты. Все изменяющие запросы — `POST` с CSRF-токеном; ответы — HTML-страницы и редиректы.

## Общие правила

- Анонимный `POST` → `302` на страницу входа; данные не меняются.
- Аутентифицированный пользователь без прав → `403`; данные не меняются.
- Несуществующий объект → `404`.
- Ошибка валидации формы → `200` с повторным показом формы и сообщениями; данные не сохраняются.
- Успешное изменение → `302` на страницу объекта (PRG-паттерн).
- Все `POST` требуют действительный CSRF-токен; иначе `403`.
- Ответы не содержат путь к файлу на диске и внутренние детали ошибок.

## Публичные страницы

| Метод | Путь | Назначение | Успех |
|-------|------|------------|-------|
| GET | `/` | Список предметов: название, число вопросов, пагинация 20; при отсутствии — сообщение | 200 |
| GET | `/subjects/<id>/` | Вопросы предмета от новых к старым, пагинация 20 | 200 |
| GET | `/questions/<id>/` | Вопрос и ответы по рейтингу (при равенстве — новые), пагинация 20; голос текущего пользователя подставляется отдельно | 200 |
| GET | `/attachments/<id>/download/` | Скачивание/просмотр вложения | 200 / 404 |
| GET | `/healthz/` | Проверка работоспособности для Docker healthcheck (Python `urllib`, `localhost` в `ALLOWED_HOSTS`) | 200 |

Страница вопроса кешируется в общем виде: текст, автор, дата, рейтинг и вложения. Голос текущего
пользователя в кеш не входит; после чтения кеша одним запросом выбираются его голоса для ответов
страницы, и в шаблоне подсвечиваются соответствующие кнопки. Анонимному посетителю голоса не
запрашиваются.

## Аутентификация

| Метод | Путь | Назначение | Успех |
|-------|------|------------|-------|
| GET, POST | `/accounts/register/` | Регистрация: имя пользователя, пароль, подтверждение | 302 на `/` после входа |
| GET, POST | `/accounts/login/` | Вход по имени и паролю | 302 на `/` или `next` |
| POST | `/accounts/logout/` | Выход | 302 на `/` |

Ошибки: занятое имя, неверный пароль, несовпадение паролей — `200` с сообщением.

## Вопросы

| Метод | Путь | Кто | Назначение |
|-------|------|-----|------------|
| GET, POST | `/subjects/<id>/questions/new/` | авторизованный | Создать вопрос в предмете |
| GET, POST | `/questions/<id>/edit/` | автор или staff | Редактировать вопрос |
| GET, POST | `/questions/<id>/delete/` | автор или staff | Подтвердить и удалить вопрос |

Поля формы вопроса: `title` (1–200), `body` (непустой). Успех создания — `302` на вопрос.
Удаление каскадно удаляет ответы, голоса и вложения и инвалидирует кеш списка предметов и
ответов вопроса.

Предметы создаются, изменяются и удаляются только в админке staff. Попытка удалить предмет с
вопросами не выполняется: staff видит сообщение «Нельзя удалить предмет, в котором есть
вопросы»; удаляется только пустой предмет.

## Ответы

| Метод | Путь | Кто | Назначение |
|-------|------|-----|------------|
| GET, POST | `/questions/<id>/answers/new/` | авторизованный | Создать ответ |
| GET, POST | `/answers/<id>/edit/` | автор или staff | Редактировать ответ |
| GET, POST | `/answers/<id>/delete/` | автор или staff | Подтвердить и удалить ответ |

Поля формы ответа: `body` (1–10 000). Успех — `302` на вопрос. Изменение или удаление ответа
инвалидирует все страницы `qa:v1:question:{id}:answers:v{version}:page:{n}` через смену версии.

## Голосование

| Метод | Путь | Кто | Тело | Результат |
|-------|------|-----|------|-----------|
| POST | `/answers/<id>/vote/` | авторизованный, не автор ответа | `value=like` или `value=dislike` | `302` на вопрос |

Семантика:

- голоса нет + `like` → создаётся лайк, рейтинг `+1`;
- голоса нет + `dislike` → создаётся дизлайк, рейтинг `−1`;
- тот же голос повторно → голос снимается, рейтинг возвращается к прежнему значению;
- другой голос → значение заменяется, рейтинг меняется на `2` в нужную сторону;
- голос за свой ответ → `403`, рейтинг не меняется;
- одновременные запросы одного пользователя → без ошибки, в итоге не более одного голоса.

После успешного коммита инвалидируются все страницы ответов вопроса через смену версии
`qa:v1:question:{id}:answers:version`.

## Вложения

| Метод | Путь | Кто | Назначение |
|-------|------|-----|------------|
| GET, POST | `/answers/<id>/attachments/new/` | только автор ответа | Добавить вложение |
| GET, POST | `/attachments/<id>/delete/` | автор ответа или staff | Удалить вложение |

Поля формы: `file`. Допустимые типы: jpg, jpeg, png, webp (≤ 5 МБ), pdf, txt, doc, docx
(≤ 10 МБ); не более 5 вложений на ответ; пустой файл и несоответствие содержимого расширению
отклоняются (`200` с сообщением). Чужой ответ → `403`. Успех — `302` на вопрос.

Скачивание отдаёт `Content-Type` из проверенного и сохранённого `content_type`, а не из запроса
клиента. Документы (pdf, txt, doc, docx) — `Content-Disposition: attachment`; изображения —
`inline`; имя файла очищено, путь на диске не раскрывается.

Добавление и удаление вложения инвалидирует все страницы ответов вопроса после коммита.

## Матрица прав

| Действие | Аноним | Пользователь | Автор объекта | Staff |
|----------|--------|--------------|---------------|-------|
| Чтение предметов/вопросов/ответов | да | да | да | да |
| Скачивание вложения | да | да | да | да |
| Создать вопрос/ответ | нет | да | — | да |
| Редактировать/удалить вопрос/ответ | нет | нет | да | да |
| Голосовать (кроме своего ответа) | нет | да (не за свой) | нет (свой ответ) | да (не за свой) |
| Добавить вложение к ответу | нет | нет | да (автор ответа) | нет, если не автор* |
| Удалить вложение | нет | нет | да (автор ответа) | да |
| Создать/изменить/удалить предмет | нет | нет | — | да (админка) |

\* staff может удалить любое вложение, но добавлять вложения в чужой ответ не может: добавление
привязано к авторству ответа.

## Кеш и побочные эффекты (сводка)

Инвалидация регистрируется в сигналах моделей `post_save`/`post_delete` и выполняется через
`transaction.on_commit` после успешного коммита. Версия ключа увеличивается, поэтому все страницы
сразу становятся недостижимы; старые записи удаляются по TTL 300 с.

| Событие | Инвалидация |
|---------|-------------|
| Предмет создан/изменён/удалён | версия `qa:v1:subjects:list:version` |
| Вопрос создан/изменён/удалён | версии `qa:v1:subjects:list:version` и `qa:v1:question:{id}:answers:version` |
| Ответ создан/изменён/удалён | версия `qa:v1:question:{id}:answers:version` |
| Голос создан/изменён/снят | версия `qa:v1:question:{id}:answers:version` |
| Вложение добавлено/изменено/удалено | версия `qa:v1:question:{id}:answers:version` |

Сигналы покрывают изменения через админку, management-команды и каскадные удаления, включая
удаление пользователя. Внутри незакоммиченной транзакции инвалидация не выполняется.
