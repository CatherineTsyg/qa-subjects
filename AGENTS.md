# AGENTS.md

Инструкции для AI-агента (opencode), работающего в этом репозитории.

## О проекте

«База данных ответов по предметам» — веб-приложение для подготовки к экзаменам.

- Предметы (категории) создаются через Django-админку.
- Пользователи задают вопросы по предмету и пишут к ним ответы.
- Ответам ставят лайк/дизлайк (один голос на пользователя, голос можно сменить или снять).
- Ответы сортируются по рейтингу (лайки − дизлайки), затем по дате.
- К ответу можно прикрепить фото и документы.

Приложение реализуется дважды:

| Папка   | Подход                                   | Стек                                         |
|---------|------------------------------------------|----------------------------------------------|
| `vibe/` | вайб-кодинг (свободные промпты)          | Django + PostgreSQL + Docker Compose         |
| `sdd/`  | Spec-Driven Development (спека → план → задачи → реализация) | то же + Valkey для кеша |

Две версии **независимы**: не импортируй код из одной папки в другую и не копируй его без явной просьбы.
Работай только в той папке, о которой идёт речь в задаче.

## Стек и версии

- Python 3.12, Django 5.x
- PostgreSQL 16 (через `psycopg[binary]`)
- Valkey 8 (только в `sdd/`), бэкенд `django.core.cache.backends.redis.RedisCache`
- Docker + Docker Compose — единственный поддерживаемый способ запуска
- Зависимости — в `requirements.txt` внутри каждой версии, версии закреплены

## Структура каждой версии

```
<vibe|sdd>/
├── docker-compose.yml
├── Dockerfile
├── .env.example        # все переменные окружения с безопасными значениями по умолчанию
├── requirements.txt
├── manage.py
├── config/             # settings, urls, wsgi
└── <apps>/             # Django-приложения
```

## Команды

Все команды выполняются из папки версии (`vibe/` или `sdd/`):

```bash
cp .env.example .env
docker compose up --build -d
docker compose exec web python manage.py migrate
docker compose exec web python manage.py createsuperuser
docker compose exec web python manage.py test
docker compose logs -f web
```

## Правила кода

- Настройки и секреты читаются только из переменных окружения. Никаких паролей и `SECRET_KEY` в коде.
- Каждое изменение моделей сопровождается миграцией (`makemigrations`), миграции коммитятся.
- Списки, которые обходят связи, используют `select_related` / `prefetch_related` / `annotate` — без N+1.
- Рейтинг ответа считается агрегатом (`Sum`/`Count` по голосам), а не хранится вручную без необходимости.
- Голос уникален по паре (пользователь, ответ) — ограничение на уровне БД.
- Изменять и удалять вопрос/ответ может только его автор (или staff).
- Загрузки: проверяй расширение и размер файла, храни в `MEDIA_ROOT` (docker volume), не отдавай пользователю путь на диске.
- Формы — через Django Forms, POST-запросы защищены CSRF.
- Новая функциональность сопровождается тестами (`django.test.TestCase`).
- Код — PEP 8, понятные имена, без закомментированного мёртвого кода.
