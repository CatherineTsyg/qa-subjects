# Quickstart: База ответов по предметам

**Feature**: `001-subject-answers` | **Date**: 2026-11-10

Пошаговая проверка, что приложение работает end-to-end. Все команды выполняются из `sdd/`.

## Предварительные требования

- Docker и Docker Compose v2.
- Свободный порт `8001` (порт `8000` не используется).
- Скопированный `.env` (см. `.env.example`).

## Запуск

```bash
cp .env.example .env
docker compose up --build -d
docker compose ps
docker compose exec web python manage.py migrate
docker compose exec web python manage.py createsuperuser
```

Ожидаемо: сервисы `db` и `valkey` — `healthy`; `web` отвечает на
`http://localhost:8001/healthz/` (healthcheck выполняется Python-скриптом через `urllib`, без
`curl`); приложение доступно на `http://localhost:8001/`, админка — `http://localhost:8001/admin/`.

Если `web` не стартует, проверить логи: `docker compose logs -f web`.

## Автоматические тесты

```bash
docker compose exec web python manage.py test
```

Ожидаемо: все тесты проходят. Покрыты модели и ограничения БД, регистрация и вход, публикация,
права автора/staff, голосование (включая гонки, голос за удалённый ответ и недопустимое значение),
вложения, CSRF-отказ на всех изменяющих POST, кеш и его инвалидация после коммита, отсутствие N+1 на
основных страницах. Все тесты используют `LocMemCache` и временный `MEDIA_ROOT` из
`config/test_utils.py`.

## Сценарии проверки

### 1. Пустая база и предметы (FR-003, FR-002)

1. Открыть `/` — ожидается сообщение об отсутствии предметов.
2. В админке создать предмет «Математика» и предмет «Физика».
3. Открыть `/` — оба предмета видны, число вопросов — `0`, сортировка по названию.
4. В админке попробовать удалить «Математику» после создания в ней вопроса — удаление не
   происходит, показывается понятное сообщение. Пустой предмет удаляется.

### 2. Регистрация и публикация (FR-004–FR-007)

1. Зарегистрироваться с именем `student` и паролем; проверить, что вход выполнен.
2. В «Математике» создать вопрос с заголовком и текстом.
3. Открыть вопрос, написать ответ.
4. Выйти и открыть страницу вопроса как аноним — вопрос и ответ видны.
5. Попробовать создать вопрос анонимом — происходит перенаправление на вход.

### 3. Голосование и порядок (FR-008–FR-011, FR-022, FR-023)

1. Создать два ответа от разных пользователей.
2. Вторым пользователем поставить лайк первому ответу — рейтинг `+1`, порядок обновился.
3. Поставить дизлайк тому же ответу — рейтинг изменился на `−2` относительно лайка.
4. Повторно нажать то же значение — голос снят, рейтинг вернулся к прежнему.
5. Попробовать проголосовать за свой ответ — `403`, рейтинг не изменился.
6. Отправить голос за удалённый ответ — `404`; отправить `value` вне `like`/`dislike` — `400`,
   голос не меняется.
7. Создать вопрос позже другого — на странице предмета он выше (от новых к старым).

### 4. Вложения (FR-012–FR-014)

1. В своём ответе приложить PNG/JPG ≤ 5 МБ и PDF ≤ 10 МБ — оба видны в ответе.
2. Скачать вложение по ссылке: изображение открывается в браузере (`Content-Disposition: inline`),
   документ скачивается файлом (`attachment`), путь на диске не раскрывается.
3. Приложить `.exe`, пустой файл, файл с содержимым не по расширению, файл > лимита — ошибка,
   файл не сохраняется.
4. Добавить 5 вложений и попробовать шестое — отказ с сообщением о лимите.
5. Другим пользователем попробовать добавить вложение к чужому ответу — `403`.
6. Автором ответа и staff удалить вложение — файл исчезает из ответа.

### 5. Права и удаление (FR-015–FR-019)

1. Вторым пользователем открыть чужой вопрос на редактирование — `403`.
2. Анонимом отправить POST на удаление — перенаправление на вход.
3. Автором удалить свой ответ — ответ, его голоса и вложения исчезают.
4. Автором удалить свой вопрос — связанные ответы и вложения исчезают.
5. Staff удаляет чужой вопрос/ответ/вложение — операция выполняется.

### 6. Кеш, страницы и инвалидация (принцип V)

1. Открыть `/` дважды; убедиться, что страница отвечает быстро.
2. Перейти на вторую страницу списка и на вторую страницу ответов — каждая страница кешируется
   отдельным ключом с номером страницы.
3. Создать вопрос; после успешного ответа список предметов показывает новое число вопросов на
   всех страницах.
4. Проголосовать; порядок ответов на странице вопроса обновляется, старый рейтинг не остаётся.
5. Проверить ключи и версии в Valkey:

   ```bash
   docker compose exec valkey valkey-cli KEYS 'qa:*'
   docker compose exec valkey valkey-cli GET 'qa:v1:subjects:list:version'
   ```

6. После каждого изменяющего действия (включая правку через админку и удаление пользователя с его
   материалами) версия соответствующего ключа увеличивается, поэтому все страницы сразу
   недостижимы. До коммита версия не меняется — это проверяется автоматическими тестами через
   `captureOnCommitCallbacks`.
7. Открыть один и тот же вопрос под разными пользователями: подсветка голоса у каждого своя,
   хотя страница берётся из общего кеша.

## Проверка производительности (SC-001, SC-007)

Наполнение детерминированными данными и замер p95 времени ответа:

```bash
# 10 000 вопросов и 100 000 ответов; команда идемпотентна и не трогает ручные данные
docker compose exec web python manage.py seed_demo

# 100 потоков, stdlib: urllib.request + concurrent.futures.ThreadPoolExecutor
docker compose exec web python scripts/benchmark_pages.py --base-url http://localhost:8001 --threads 100
```

Скрипт замеряет `/`, `/subjects/<id>/` и `/questions/<id>/`, печатает число запросов, p50 и p95.
Результат (дата, конфигурация, p95 по каждой странице) записывается в этот раздел. Целевой
показатель: p95 менее 1 с на каждой из трёх страниц.

Результаты замера: _заполняется при выполнении T073/T076_.

## Проверка ограничений и ошибок

- Повторная регистрация с занятым именем — сообщение, учётная запись не создаётся.
- Вопрос без заголовка или ответ без текста — ошибка формы, данные не сохраняются.
- Заголовок длиннее 200 символов, ответ длиннее 10 000 — ошибка формы.
- Открыть несуществующий вопрос/вложение — `404`.
- POST без CSRF-токена — `403`.

## Остановка и сброс

```bash
docker compose down          # остановить, данные сохранить
docker compose down -v       # остановить и удалить данные (БД и media)
```
