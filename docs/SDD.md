# Отчёт «на 5»: SDD-версия

Подход: Spec-Driven Development через [GitHub Spec Kit](https://github.com/github/spec-kit) —
конституция → спецификация → уточнение → план → задачи → анализ → реализация.

- Агент: opencode, модель `opencode/deepseek-v4.1-flash-free` (та же, что для `vibe/`)
- Артефакты SDD: `sdd/.specify/` (конституция, шаблоны), `sdd/specs/<фича>/` (spec.md, plan.md, tasks.md и др.)

## Подготовка

```bash
pipx install specify-cli          # specify-cli 1.3.3
cd sdd
specify init --here --force --non-interactive --integration opencode --script sh
```

Init создал `sdd/.specify/` (шаблоны, скрипты, конституция) и `sdd/.opencode/commands/speckit.*.md` (9 команд).
Расширение git не подключалось — ветки под фичи Spec Kit не создаёт.

opencode запускается из папки `sdd/`, чтобы подхватить команды `/speckit.*` из `sdd/.opencode/commands/`.

## Шаги

### 1. `/speckit.constitution`

```
/speckit.constitution Принципы проекта:
- Код живёт только в папке sdd/, папку vibe/ не читать и не использовать.
- Стек: Python 3.12, Django 5.x, PostgreSQL 16, Valkey 8 для кеша, запуск только через docker compose. Веб-порт по умолчанию 8001 (8000 занят другой версией).
- Безопасность: секреты только из переменных окружения, DEBUG по умолчанию False, CSRF на всех POST, права на изменение — только у автора или staff.
- Целостность данных: инварианты (уникальность, допустимые значения) — ограничениями в БД; связанные изменения — в одной транзакции.
- Производительность: без N+1 запросов; часто читаемые и редко меняющиеся данные кешируются в Valkey с явной инвалидацией.
- Тесты обязательны для каждого пользовательского сценария, включая запреты и граничные случаи; тесты кеша проверяют инвалидацию.
- Простота: без лишних абстракций и зависимостей сверх необходимого.
```

Результат: _что получилось в `.specify/memory/constitution.md`_.

### 2. `/speckit.specify`

```
/speckit.specify «База ответов по предметам» — сервис для подготовки к экзаменам.
Администратор заводит предметы (категории). Пользователи регистрируются и входят в систему.
Пользователь может задать вопрос по предмету. К вопросу пользователи пишут ответы.
Ответу можно поставить лайк или дизлайк; ответы с самым высоким рейтингом показываются первыми.
К ответу можно прикрепить фото и документы.
Автор может редактировать и удалять свои вопросы, ответы и вложения.
Списки предметов и ответов должны открываться быстро даже при большом числе пользователей.
```

Результат: _ссылка на spec.md, user stories и критерии приёмки_.
