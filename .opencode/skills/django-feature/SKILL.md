# Добавление фичи в Django-проект

Выполняй шаги по порядку. Работай внутри одной версии (`vibe/` или `sdd/`), все команды — из её папки.

## 1. Уточни задачу

- Какие сущности и поля нужны, кто имеет доступ, какие есть ограничения.
- Если что-то неясно — спроси пользователя до написания кода.

## 2. Модель

- Добавь модель в `models.py` нужного приложения.
- Обязательно: `__str__`, `class Meta` с `ordering` (если уместно), `related_name` у FK.
- Уникальность и инварианты — через `constraints` (`UniqueConstraint`, `CheckConstraint`), а не только в коде.
- Для файлов — `FileField`/`ImageField` с `upload_to` и валидаторами (`FileExtensionValidator` + проверка размера).

## 3. Миграция

```bash
docker compose exec web python manage.py makemigrations
docker compose exec web python manage.py migrate
```

Проверь сгенерированный файл миграции глазами.

## 4. Админка

Зарегистрируй модель в `admin.py`: `list_display`, `search_fields`, `list_filter`; для slug — `prepopulated_fields`.

## 5. Форма, вью, URL

- Форма — `ModelForm` с явным списком `fields` (никогда `__all__`).
- Вью: доступ на запись — `LoginRequiredMixin` / `@login_required`; правка и удаление — только автору.
- Изменяющие действия (голос, удаление) — только `POST`.
- Запросы списков — с `select_related`/`prefetch_related`/`annotate`, без N+1.
- URL — с `name=`, в шаблонах используй `{% url %}`.

## 6. Шаблон

Наследуйся от `base.html`, выводи ошибки формы, добавляй `{% csrf_token %}` в каждую POST-форму, у форм с файлами — `enctype="multipart/form-data"`.

## 7. Кеш (только `sdd/`)

Если данные читаются часто, а меняются редко — кешируй через `django.core.cache`.
Ключи — с префиксом сущности (`answers:question:<id>`), инвалидация — при каждом изменении (сохранение, удаление, новый голос).

## 8. Тесты

В `tests.py` (или `tests/`) приложения добавь как минимум:

- успешный сценарий;
- запрет для анонима / чужого пользователя;
- граничный случай (повторный голос, недопустимый файл и т.п.).

```bash
docker compose exec web python manage.py test
```

## 9. Итог

Кратко перечисли пользователю: изменённые файлы, новые URL, как проверить руками. Предложи сообщение коммита в стиле Conventional Commits (`feat: ...`, `fix: ...`).
